FEATURE 2 — COLLECT RESPONSES

Add to the form block type:
- collectResponses: boolean (default false)
- responsesOpen: boolean (default true)

In the block editor, add a "Collect responses" checkbox and, when it is on, an "Accepting submissions" toggle.

Participant side: when collectResponses is true, show a "Submit" button next to the existing Copy button. Submit sends the assembled text (same text the Copy button produces) to the server. On success, show "Submitted" with a checkmark and change the button to "Resubmit". If responsesOpen is false, show "Submissions closed" and disable the button. Notes autosave is unchanged; Submit is a separate explicit action.

New table: form_responses
- id, cohort_id, participant_id, section_id, block_index (integer position of the form block in the section), form_name, response_text, created_at, updated_at
- Unique on (participant_id, section_id, block_index). Resubmitting updates the row.

New endpoints (Zod safeParse, req.log, existing auth middleware):
- POST /api/responses — participant; body { sectionId, blockIndex, responseText }. Rejects if the block is not a form with collectResponses true, or if responsesOpen is false, or if the section is not unlocked for the participant (reuse lib/section-access.ts).
- GET /api/admin/cohorts/:cohortId/responses?sectionId=&blockIndex= — admin; returns all responses for the cohort, newest first, with participant name, section title, form_name. Filters optional.

Add the participant endpoint to lib/api-spec/openapi.yaml and run codegen.
