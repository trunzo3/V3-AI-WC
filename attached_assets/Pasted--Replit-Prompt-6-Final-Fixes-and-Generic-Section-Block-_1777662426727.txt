## 8. Generic Section Block Editor

### Data Model Change

In the generic_sections table:
- Remove the content column (text)
- Remove the prompt_block column (text, nullable)
- Add content_blocks column (jsonb, not null, default '[]')

The content_blocks column stores an ordered array of block objects. Each object has two fields: type (either "text" or "prompt") and content (a string). For text blocks, content is HTML from the WYSIWYG editor. For prompt blocks, content is plain text.

Example value:
[{"type":"text","content":"<p><strong>Think about a real update</strong> you need to send...</p>"},{"type":"prompt","content":"You are an experienced HHS program manager. Draft a one-paragraph status update..."},{"type":"text","content":"<p>Now review the output. Did it capture your tone?</p>"},{"type":"prompt","content":"Rewrite the update above for a non-technical audience..."}]

- No other block types beyond "text" and "prompt"
- Array position determines render order
- The goal_text field stays as its own separate column — it is NOT part of the block system

### Admin UI — Block Editor

Replace the current body content textarea and prompt block textarea in the generic section create/edit dialog with a block editor.

Layout:
- Goal text field stays at the top (plain text input, same as now)
- Below it: the block editor area showing all blocks in order
- At the bottom of the block editor: two buttons side by side: "+ Add text block" and "+ Add prompt block"

Each block in the editor:
- Shows its type label ("Text block" or "Prompt block") in muted text
- Has up/down arrow buttons on the left for reordering
- Has a remove button (red X or trash icon) on the right
- Text blocks render the WYSIWYG Tiptap editor (with B, I, U, H2, H3, bullet list, ordered list, link, blockquote, undo/redo toolbar)
- Prompt blocks render a plain textarea (monospace font) with a label "Prompt text (participants can copy this)"

Save behavior:
- On save (Create or Save Changes), serialize the entire block list as a JSON array and write it to content_blocks
- Full array replace on every save — never diff or patch individual blocks
- Read the full array on load and populate the editor

Reorder behavior:
- Up arrow swaps the block with the one above it
- Down arrow swaps the block with the one below it
- First block's up arrow is disabled, last block's down arrow is disabled
- After reorder, the editor re-renders with updated positions — no save needed until the user clicks Save

### Participant Side — GenericSectionView

Update the GenericSectionView component to render from content_blocks.

Render order from top to bottom:
1. EXERCISE or REFERENCE badge
2. Section Title
3. Goal box (if goal_text exists)
4. All blocks rendered in array order
5. YOUR NOTES auto-save textarea at the bottom

Text block rendering:
- Render the HTML content using dangerouslySetInnerHTML
- Wrap in a div with appropriate prose styling (font-size 14px, line-height 1.7, standard margins between paragraphs)

Prompt block rendering:
- Navy background box (#1A2744), border-radius 10px, padding 20px
- Label in gold pill at top-left: "PROMPT 1", "PROMPT 2", etc. — numbered sequentially among prompt blocks only (not by position in the full block list)
- Copy button at top-right: same CopyButton component used in hardcoded sections
- Plain text content in white/light color, monospace font, white-space pre-wrap
- Margin between blocks: 12px between consecutive prompt blocks, 24px between a text block and a prompt block

Prompt numbering logic: If blocks are [text, prompt, text, prompt, prompt], the prompts are labeled "Prompt 1", "Prompt 2", "Prompt 3". Text blocks do not affect the prompt counter.

### Backward Compatibility

If a generic section has the old content and prompt_block columns populated but content_blocks is empty or missing, migrate on read: construct a content_blocks array from the old fields. Put the old content as a text block first, then the old prompt_block as a prompt block second. This way existing generic sections don't break.

Alternatively, run a one-time migration in the seed script that converts any existing generic sections with old-format data into the new content_blocks format.

### PDF Export

- Prompt blocks render as styled boxes matching the navy prompt block design, with "PROMPT 1" / "PROMPT 2" labels. No copy button in PDF.

### API Changes

- PUT /admin/generic-sections/:id — same
- GET /admin/generic-sections — return content_blocks
- The participant-facing section data should include content_blocks for generic sections
- Update the OpenAPI spec and run codegen

## 9. Prompt Label Numbering

This is part of item 8 but called out explicitly for clarity.

Prompt blocks are numbered sequentially among themselves, not by their position in the block list. Example:

- Block 1: text block (no label)
- Block 2: prompt block (labeled "Prompt 1")
- Block 3: text block (no label)
- Block 4: prompt block (labeled "Prompt 2")
- Block 5: prompt block (labeled "Prompt 3")

The numbering counter only increments for prompt-type blocks.
